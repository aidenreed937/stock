# 量化系统数据底座与 PIT 设计规范

在从量化投研向实盘交易转换的过程中，底层数据的严谨性决定了回测的生死。本规范主要规定了 A 股数据处理中最核心的三个防坑机制：**PIT（无未来函数财务切片）**、**复权价格引擎分离**以及**多频日历对齐**。

---

## 一、 PIT (Point-in-Time) 财务数据引擎设计

A 股上市公司的财报披露存在严格的周期要求，一份年报或季报往往会经历“业绩预告 -> 业绩快报 -> 正式财报”三个阶段。如果在回测时直接使用带有未来属性的 `end_date`（报告期）作为索引，会导致严重的 Look-ahead bias（未来函数）。

### 1. 数据源集成映射
财务分析引擎必须同时集成三个 TuShare 端点，并建立优先级机制：
*   `forecast` (业绩预告)：最早发布，给出净利润区间的上下限。
*   `express` (业绩快报)：随后发布，数据更精确但科目不全。
*   `income` / `balancesheet` / `cashflow` (正式财报)：最晚发布，数据绝对准确且详尽。

### 2. 核心索引规则 (The Golden Rule)
任何财务数据表在进入 `data/curated` 层（以及提供给因子引擎使用时），**必须以 `ann_date` (公告日) 作为唯一可视时间轴**。`end_date` (报告期) 仅作为区分财务周期的业务字段，绝不能用于时间序列排序或连接（Join）。

### 3. 多版本覆盖与置信度标记 (`update_flag`)
当同一报告期（如 Q3）的数据在时间轴上随着时间推移发生更新时，系统需记录当前时点的有效信息类型。
设计 `report_type` (或 `update_flag`) 字段：
*   `1`：当前使用的是**业绩预告**的均值估算。
*   `2`：当前使用的是**业绩快报**。
*   `3`：当前使用的是**正式财报**。

下游多因子选股或行业打分卡在使用 ROE 边际改善等指标时，可以根据 `report_type` 赋予不同的置信度权重（例如，正式财报权重最高，预告最低）。

## 二、 复权 (Adjustment) 与交易价格机制

量价因子的计算（动量、波动率）与实盘仓位的计算存在天然的冲突：
*   因子计算要求价格连续（需要复权）。
*   实盘报单和可用资金计算要求价格真实（不能复权）。

### 1. 存储层极简原则
*   `data/curated/daily` 仅存储**不复权**的原始真实 OHLCV 价格。
*   独立维护 `data/curated/adj_factor` (复权因子表)。

### 2. 动态计算层分离
业务 Domain 层需提供一个通用的价格转换器（Adjustment Engine）：
*   **回测引擎调用**：通过原始价格和复权因子，动态计算前复权 (qfq) 或后复权 (hfq) 数据框。推荐统一使用**后复权 (hfq)** 来保障过去的价格不随未来的除权除息发生变动，保证截面因子的稳定性。
*   **实盘交易/滑点模拟调用**：直接读取不复权价格，并根据除权除息日判定当日的真实涨跌停板阈值。

## 三、 交易日历与频率对齐

量化系统常面临月度（宏观）、季度（财务）、日度（行情）甚至更高频数据的混合计算。

### 1. 以国内交易日为唯一主轴
建立全局单例的 `TradeCalendar`，以 TuShare `trade_cal` 为系统跳动的主时钟。所有因子面板数据（Panel Data）必须 Join 到这个日历上。

### 2. 安全的前向填充 (Safe FFill)
当对低频数据（如宏观的社融、M1）向高频（日度）扩展，或者处理海外节假日导致的外盘数据缺失时：
*   **发布日约束**：前向填充必须且只能从数据**真实向公众发布的次日**开始执行。
*   绝对禁止使用插值法（Interpolation）和简单平滑，因为这会引入未来的斜率信息。对于停牌标的，保留其最后一个交易日的收盘价，但当日成交额强制归 `0`。

### 3. 冲击成本与流动性限制预留
日线数据在入库时，需衍生计算 `avg_turnover_20d` (20日日均成交额) 等流动性指标。在构建“行业打分表”时，系统应能够根据配置的“虚拟资金体量”，直接将该股票的期望权重与其实际流动性挂钩，拒绝配置会导致超过日均成交 5% 的头寸。
