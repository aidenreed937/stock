# 报告一致性校验

## 目的

确认分析报告可以追溯到本地事实、配置和已发布的上游产物，避免不同报告之间日期、运行关系或核心结论串线。

## 命令

~~~bash
make report-consistency
make report-consistency DATE=YYYY-MM-DD
make report-consistency START=YYYY-MM-DD END=YYYY-MM-DD
~~~

具体参数和输出选项以当前脚本的 --help 为准。

## 校验重点

校验程序负责检查当前实现定义的产物完整性、观测日一致性、上下游运行引用、报告与机器可读结果的一致性，以及已配置的无源叙事和数据截点约束。不要在本文复制检查项清单；新增校验规则应以程序输出为准。

校验通过不等于数据质量自动合格。仍需查看每个运行目录的质量报告，重点关注数据缺失、滞后、外部事实截点、行业趋势诊断和温度降级。

## 使用要求

- 跨周期研究、案例复盘和对外输出前，先运行一致性校验。
- 校验失败时停止投资判断，只报告失败项和需要修复的产物。
- 产物选择以 Manifest 的观测日和上游关系为准，不以 latest 名称或目录修改时间推断。
- 批量任务应先生成和校验运行目录，最后再发布选定日期的 latest。
- 运行唯一性和发布事务由共享产物存储实现负责，不在文档中假设 run_id 的时间精度或自行拼接运行目录。
- 若批量流程需要刷新 Mart，使用代码提供的增量入口；覆盖式重建必须有明确任务、备份和恢复方案。

## 结果表达

一致性校验只能回答“产物是否串线或无法追溯”，不能替代事实质量判断。最终输出仍需区分已验证事实、机制判断和数据限制。
