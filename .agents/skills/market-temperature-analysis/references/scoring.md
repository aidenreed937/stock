# 市场温度评分结果阅读指南

## 用途

本文件帮助阅读市场温度评分结果，不复制当前指标清单、权重或公式。评分行为以当前配置和实现为准；本文与代码不一致时，以代码、配置、测试和运行产物为准。

## 事实来源优先级

1. 当前分析配置：决定窗口、维度、指标启停、方向和质量约束。
2. 当前评分实现：决定温度转换、聚合、缺失处理和风险摘要。
3. 单次运行产物：Manifest 记录观测日期、运行关系和数据截点；facts 记录事实与水位；scores 记录评分结果；质量报告记录可用性和警告。
4. 本文和其他参考资料：只提供阅读框架，不是评分契约。

需要确认某个指标或字段时，不要从本文抄公式或字段名；查看对应 CLI、配置、代码和实际产物。

## 推荐阅读顺序

1. 先看 Manifest：确认观测日、交易窗口、上游运行和数据截点。
2. 再看质量报告：确认必需数据是否可用、是否滞后、是否存在硬错误。
3. 再看 facts：区分事实日期、窗口、样本量、状态和是否为观察项。
4. 最后看 scores 和报告：理解各维度、综合状态、风险摘要以及因数据缺失产生的降级。

评分阅读时始终区分：

- 综合温度：整体风险环境和参与条件的摘要；
- 六维结果：解释综合状态由哪些方面推动或拖累；
- 短线结果：节奏观察，不自动等同于中期趋势；
- 行业结构：独立的方向筛选结果，不是综合温度的第七个维度；
- 外部冲击：隔夜观察，未经过下一交易日确认时不能表述为 A 股风险已经传导。

## 数据与解释约束

- 缺失或滞后数据必须保留在结论中，不能用默认值补齐。
- 低频基本面和宏观数据说明当前底座，不应被写成窗口内每天发生的变化。
- 资金、估值和行业结果要同时注明事实日期或数据水位，不能只引用市场观测日。
- 事实、机制判断和数据限制分开表达。
- 结果中的仓位或风险闸门字段是管线输出，不能被重新解释成脱离用户风险约束的个性化投资建议。

## 运行与变更

标准生成入口：

~~~bash
make market-temperature DATE=YYYY-MM-DD
~~~

需要比较两个观测日时，使用当前 CLI 支持的比较参数；需要多日期时使用批量脚本并先查看 --help。不要手工调用指标列表拼装一个“等价评分”。

如果需求是调整评分：

- 调整权重、方向、启停或质量约束，修改配置并补测试；
- 调整事实、温度转换或缺失处理，修改对应实现并补测试；
- 调整报告表达，修改 Reporting 层；
- 只有用户可见的解释或工作流变化时，才更新本参考文档。

## 最小验收

- 运行成功并生成对应产物；
- Manifest 的观测日和上游关系符合请求；
- 质量报告没有被忽略的硬错误；
- 报告中的结论可以追溯到 facts、scores 和配置；
- 批量或跨周期任务在发布前通过区间一致性校验。
