# 行业结构结果阅读指南

## 定位

行业结构是中观方向筛选模块。市场温度回答整体风险环境，行业结构回答方向和轮动在哪里。行业结构分不并入六维综合温度。

~~~text
市场温度 -> 整体风险环境和参与条件
行业结构 -> 行业排序、轮动、拥挤与结构风险
~~~

## 工作流

需要生成或刷新行业结构时，使用标准入口：

~~~bash
make industry-structure DATE=YYYY-MM-DD
~~~

应优先使用与市场温度相同的观测日。运行后依次核对运行目录、Manifest、质量报告和行业报告；批量任务在发布前执行区间一致性校验。参数和产物结构以当前 CLI、配置和 Manifest 为准。

## 阅读顺序

1. 先看结构健康度：短期扩散、中期确认、领先行业的中期收益和拥挤行业占比。
2. 再看结构排序：领先主线、低估改善、强势但拥挤、落后或偏弱方向。
3. 再看行业事实：动量、估值、基本面、拥挤和资金确认是否互相支持。
4. 最后看质量信息：行业行情是否覆盖基准日，基本面是否滞后，行业映射和资金事实是否缺失。

## 解释原则

- 结构分是排序工具，不是买入信号，也不是风险环境分。
- 短期上涨而中期未确认时，只能描述为修复或价格先行，不能直接称为趋势反转。
- 高成交或强势行业可能同时存在拥挤风险；热门不等于低风险。
- 正式财报和其他低频基本面是底座，公告或预期类事实只能按实际覆盖和水位表达。
- 行业资金流是确认或风险观察，除非当前配置和实现明确纳入，否则不要自行把它加进结构分。
- 标签和分组以当前产物为准，不在文档中维护阈值或手工重排。

## 数据限制

缺失行业映射、行情、资金或基本面时，保留 missing、unavailable 或 insufficient 等不可用状态；不要把缺失当作零，也不要用行业名称或模型记忆补数据。

行业财报有季频滞后，不能写成最近若干交易日内发生的变化。行业结构结论必须同时说明观测日和关键数据水位。

## 事实来源与维护

当前行业配置决定窗口、子分、标签和质量约束；行业管线决定事实、评分和报告。本文只解释如何使用结果。新增数据源、字段、权重或阈值时不在本文复制实现细节，只有用户可见的阅读规则或工作流变化时才更新。
