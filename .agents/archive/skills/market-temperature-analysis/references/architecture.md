# 市场温度分析的架构边界

## 用途

本文件只说明分析系统的职责边界和扩展落点，不维护类名、字段清单、路径映射或具体评分公式。实现细节以当前代码、配置、测试和运行产物为准。

## 数据流

~~~text
本地 Curated 数据
  └─> 特征集市 / 领域 Mart（事实加速，可选观察事实）
        ├─> 可复用指标
        └─> 领域派生事实
              └─> 市场温度事实层
                    ├─> 配置驱动评分
                    ├─> 质量校验
                    └─> 报告与产物发布

本地行业数据
  └─> 行业结构管线
        └─> 行业排序、结构诊断和行业报告
~~~

市场温度和行业结构是同级分析管线。市场温度回答整体风险环境，行业结构回答方向和轮动；行业结构分不直接并入六维综合温度。投资者简报和量化投研简报是上游产物的解释层，不重新计算上游指标。

## 职责边界

- 数据目录和 Curated 层提供可追溯事实，不负责市场温度的解释。
- 特征集市和领域 Mart 负责事实整理与加速，不决定市场温度权重。
- 可复用指标层服务多个分析场景，不依赖某一条具体管线。
- 市场温度管线负责交易窗口、事实收集、评分、质量结果和市场温度报告。
- 行业结构管线负责行业面板、结构排序、轮动诊断和行业报告。
- Reporting 层负责把已生成的事实、分数和质量结果渲染成可读报告，不绕过事实层重新计算。
- 共享 ArtifactStore 负责运行目录、临时写入、发布、latest 和生命周期治理；各管线 adapter 只负责自己的 Payload 业务模型。

## 扩展落点

遇到新需求时按职责选择位置：

| 需求 | 归属 |
|---|---|
| 多场景都能复用的指标 | 通用指标层 |
| 只服务市场温度的派生事实 | 市场温度管线 |
| 只服务行业排序的指标或诊断 | 行业结构管线 |
| 权重、方向、启停或质量约束 | 对应分析配置 |
| 报告文案、表格和展示格式 | Reporting 层 |
| 运行目录、临时文件、发布和清理 | 共享产物存储层 |

不要因为新增一个指标就修改 skill 或复制一份手工计算；先确认它属于事实、评分还是展示层。

## 不变量

- 可复用指标层不依赖具体分析管线。
- 报告层不使用模型记忆补齐缺失事实。
- 缺失事实保留不可用状态，不静默替换为零或默认值。
- 下游简报按同一观测日和已校验的上游运行生成。
- 批量产物先完成一致性校验，再发布共享展示副本。

## 事实来源与维护

代码和测试定义行为，YAML 定义配置，Manifest 和质量报告记录单次运行事实；本文件只解释边界。内部模块重命名、字段新增或公式调整不需要同步改本文，只有用户可见的职责边界或工作流发生变化时才更新。
